### 1\. 谁想做什么？遇到了什么痛点？

想象一下，你是一所大学的网络中心主任。学校接到匿名举报，称某位教务管理人员可能利用职务之便，篡改了学生的成绩数据。校领导要求你立即对这位管理人员使用的办公电脑进行电子数据取证，以查明真相。

**你面临的痛点是什么？**

- **数据量大且敏感** ：电脑里存有全校数万学生的成绩记录，数据量巨大，且必须保密。
- **证据易被破坏** ：如果你直接打开电脑检查，任何操作（比如不小心修改了文件时间）都可能破坏原始证据的真实性，导致结果在法律上无效。
- **需要可复现性** ：调查过程必须能被第三方机构（例如司法鉴定中心）重复验证，确保结果公正。

**旧方法为何无效？**

过去，有人可能会直接登录系统，把可疑文件复制出来分析。这种方法的问题是：

- **改变了证据** ：复制操作会改变文件的“最后访问时间”等元数据，破坏了原始状态。
- **无法证明完整性** ：你怎么向别人证明，你分析的文件和原始硬盘上的文件一模一样，没有被你无意中修改过？
- **容易遗漏** ：手动复制可能会漏掉隐藏文件、磁盘碎片中的残留数据等关键证据。

**案例对比** ：这就好比警察调查一个传统案件的物证（比如一把刀）。正确的做法是戴着手套，将物证放入证物袋密封，贴上标签，记录所有经手人。而错误的做法就是直接用手拿着刀翻来覆去地看，这样会在上面留下自己的指纹，破坏了证据。

### 2\. 新解决方案的核心：取证镜像

为了解决上述痛点，数字取证领域引入了 **镜像技术** 。它的核心思想非常简单却极其重要：

> **为原始数据制作一个完美的、位对位的“数字副本”（即镜像），所有后续的分析工作都只在这个副本上进行。**

**核心差异与适用条件**

- **核心差异** ：镜像技术 **不关心** 文件的具体内容（比如它是Word文档还是图片），它只关心存储介质上最底层的“0”和“1”的排列顺序。它会把整个硬盘扇区一个接一个地、原封不动地复制下来，包括已删除文件的空间、系统空闲区域等。而普通复制只复制当前可见的文件。
- **适用条件** ：只要是需要确保电子证据 **完整性、真实性和不可否认性** 的场景，都必须使用镜像技术。这在教育、金融、司法等领域是基本要求。

**一个简单的比喻**  
你可以把硬盘想象成一盘珍贵的、不能重复录制的录像带。取证镜像就像是使用一台专业的克隆机，将这盘录像带 **连同所有内容（包括空白间隙）** 完整地复制到另一盘空白带上。以后我们所有的“播放”和“分析”都只用那盘复制带，原始录像带则被安全地锁进保险柜。

### 3\. 实战演练：为教育行业场景构建取证镜像环境

现在，我们开始动手。假设我们要调查的是一台运行Linux系统的教务管理服务器。

#### 第一步：数据准备与环境隔离

1. **目标设备** ：假设目标硬盘是 `/dev/sdb` （ **非常重要：操作前务必确认设备名，误操作会导致数据丢失！** ）。
2. **操作机** ：准备另一台干净的、安装有Linux系统的电脑作为我们的取证工作机。
3. **存储介质** ：准备一个容量 **大于** 目标硬盘的空白移动硬盘，用于存放镜像文件，我们将其挂载到 `/mnt/evidence` 。
![image](./屏幕截图%202026-03-30%20162102.png)
#### 第二步：安装必要工具

在取证工作机上，打开终端，安装核心工具：

```bash
# 更新软件包列表
sudo apt-get update

# 安装取证工具包（包含dd、dcfldd等）、哈希计算工具、自动取证分析工具
sudo apt-get install dcfldd hashdeep sleuthkit autopsy -y
```
![image](./屏幕截图%202026-03-30%20161914.png)
- `dcfldd` ：是 `dd` 命令的增强版，自带哈希校验和进度显示，更适合取证。
- `sleuthkit` / `autopsy` ：强大的开源取证分析平台，我们后面会用来自动分析镜像。

#### 第三步：法律合规要点实操（重中之重！）

在进行任何操作前，我们必须遵守法律合规流程：

1. **只读原则（软件写保护）** ：  
	在将目标硬盘连接到取证工作机后， **立即** 执行以下命令，将其设置为只读模式，防止误写操作。

```bash
sudo blockdev --setro /dev/sdb
验证是否设置成功：
sudo blockdev --getro /dev/sdb
如果返回 \`1\`，则表示成功设置为只读。
```
![image](./屏幕截图%202026-03-30%20161946.png)
2\. **开始制作镜像并记录证据链**

```
A. 磁盘全盘镜像（最核心步骤）
我们使用 \`dcfldd\` 命令制作全盘镜像，并在过程中计算哈希值（证据链的关键）。根据国家密码管理局的要求，我们使用商用密码算法SM3来计算哈希值。
```
```bash
# 切换到证据存储目录
    cd /mnt/evidence
    # 开始制作镜像
    sudo dcfldd if=/dev/sdb of=./server_disk_image.img bs=4K hash=sm3 hashwindow=1G hashlog=./sm3_hashes.txt
```
![image](./屏幕截图%202026-03-30%20161117.png)
如图所示，由于发现不支持SM3，所以这里先采用sha256代替。
```
sudo dcfldd if=/dev/sdb of=./server_disk_image.img bs=4k hash=sha256 hashwindow=1G hashlog=./sha256_hashes.txt
```
```
*   \`if=/dev/sdb\`：输入文件（Input File），即我们的目标硬盘。
*   \`of=...img\`：输出文件（Output File），即生成的镜像文件。
*   \`bs=4K\`：设置块大小，4K通常效率较高。
*   \`hash=sha256\`：指定使用sha256算法进行哈希计算。
*   \`hashwindow=1G\`：每复制1GB数据就计算并记录一次哈希值。
*   \`hashlog=...txt\`：将所有的哈希值记录到指定文件。

这个过程会比较长，耐心等待。完成后，\`dcfldd\` 会给出整个镜像的最终sha256哈希值。
```

3\. **原始证据隔离**  
	镜像制作完成后， **立即** 将原始硬盘从工作机上卸载，并贴上标签，注明时间、操作人、案件编号，然后进行物理封存（如放入防静电袋密封）。后续所有分析绝不再接触原始硬盘。

### 4\. 简化的认知框架

请你记住取证镜像的三个核心原则，我把它称为 **“取证三不”** 原则：

1. **不直接碰原始证据** （用镜像代替）。
2. **不破坏证据状态** （操作前写保护）。
3. **不让证据链断裂** （全程记录哈希和时间戳）。

### 5\. 迁移到其他领域

这套方法不仅适用于教育行业。

- **企业合规审计** ：调查员工是否泄露公司机密。
- **网络安全事件响应** ：分析被黑客入侵的服务器。
- **个人数据恢复** ：从损坏的硬盘中最大限度恢复重要数据。
